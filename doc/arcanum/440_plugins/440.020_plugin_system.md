# Plugin System
> Source: `11_skills_system.md`, `21_feature_flags.md`

## Overview

Plugins are the top-level extensibility unit. They can provide skills, hooks, MCP servers, and commands. Two categories: **marketplace plugins** (installed from registries) and **built-in plugins** (ship with CLI, user-toggleable).

## Built-in vs Bundled Skills

| Property | Bundled Skills | Built-in Plugins |
|----------|---------------|-----------------|
| Visibility | Always loaded | Appear in `/plugin` UI |
| Toggle | Cannot disable | User can enable/disable |
| Persistence | N/A | Saved to `settings.enabledPlugins` |
| Components | Single skill | Skills + hooks + MCP servers |

## Plugin Management Commands

| Command | Purpose |
|---------|---------|
| `/plugin` (aliases: `/plugins`, `/marketplace`) | Browse, install, manage plugins |
| `/reload-plugins` | Activate pending plugin changes |

## Plugin Settings

- `enabledPlugins`: `Record<string, boolean\|string[]>` -- plugin ID@marketplace format
- `extraKnownMarketplaces`: Additional marketplace sources
- `strictKnownMarketplaces`: Enterprise-only: restrict to these sources
- `pluginConfigs`: Per-plugin options and MCP server configs

## Migration to Plugins

Active commands (`/pr-comments`, `/security-review`) are migrating to plugins via `createMovedToPluginCommand()` pattern, which shows a message directing users to install the plugin version.

## Enterprise Controls

- `strictPluginOnlyCustomization`: Lock customization to plugins only
- `blockedMarketplaces`: Block specific marketplace sources
- Plugin hooks respect `allowManagedHooksOnly` policy

## Key Source Files
