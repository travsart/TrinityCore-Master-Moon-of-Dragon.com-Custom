# Permission Evaluation Order
> Source: `10_permissions.md`

## Core Pipeline (`hasPermissionsToUseTool()`)

```
--- Bypass-immune checks (run first) ---
1a. Deny rule for entire tool?          -> DENY
1b. Ask rule for entire tool?           -> ASK
1c. Tool.checkPermissions()             -> tool-specific result
1d. Tool denied?                        -> DENY
1e. Tool requires user interaction?     -> ASK
1f. Content-specific ask rule?          -> ASK (bypass-immune)
1g. Safety check (sensitive paths)?     -> ASK (bypass-immune)

--- Mode-based decisions ---
2a. bypassPermissions mode?             -> ALLOW
2b. Entire tool in allow rules?         -> ALLOW
 3. Passthrough -> ask with suggestions

--- Post-processing ---
 4. dontAsk mode? -> convert ASK to DENY
 5. auto mode? -> run YOLO classifier pipeline
 6. headless/background? -> hooks, then auto-deny
```

## Auto Mode (YOLO Classifier) Pipeline

When `ask` result in auto mode:
1. Non-classifier-approvable safety check? -> keep ASK
2. Would `acceptEdits` mode allow this? -> ALLOW (fast path)
3. Tool on safe allowlist? -> ALLOW (fast path)
4. Run YOLO classifier -> ALLOW or DENY
5. Classifier unavailable? -> DENY (fail closed) or ASK (fail open)
6. Denial limit exceeded? -> fall back to ASK

## Key Design Principles

- **Deny wins first**: Always checked before allow or mode overrides
- **Defense in depth**: Rules, path safety, Windows pattern detection all run independently
- **Fail closed**: Auto-mode classifier defaults to deny when unavailable
