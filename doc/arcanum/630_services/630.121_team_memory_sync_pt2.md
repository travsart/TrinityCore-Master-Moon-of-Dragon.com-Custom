## Interesting Findings

1. **No client-side entry count cap.** The server's limit is org-configurable via GrowthBook (`claude_code_team_memory_limits`). The client only learns the limit from a structured 413 response's `extra_details.max_entries` field.

2. **Gateway vs app 413 ambiguity**: The API gateway rejects bodies over ~256-512KB with an unstructured HTML 413 before the request reaches the app server. The client distinguishes them by response format -- structured JSON = app, HTML = gateway.

3. **The `view=hashes` endpoint** fetches only metadata and checksums, skipping entry bodies. This is used for delta detection: compare local content hashes against server checksums to determine what needs pushing.

4. **Delta push is critical for performance** -- cold pushes from heavy users were hitting 300KB-1.4MB, triggering gateway 413s. Splitting into sequential PUTs with upsert-merge semantics fixes this.
