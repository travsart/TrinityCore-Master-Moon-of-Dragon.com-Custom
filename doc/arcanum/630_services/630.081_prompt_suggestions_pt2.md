## Interesting Findings

1. **Cache sharing is paramount.** The suggestion fork deliberately avoids overriding ANY API parameter -- even `effortValue: 'low'` caused a 45x spike in cache writes (92.7% to 61% hit rate, PR #18143). The only safe overrides are client-side: abort controller, skip transcript, skip cache write, canUseTool.

2. **Tool denial is via callback, not empty tool list.** Passing `tools: []` would bust the prompt cache (tools are part of the cache key). Instead, tools are kept in the request but denied via `canUseTool` callback.

3. **Speculation uses copy-on-write semantics.** Files are only copied to the overlay when first written. Reads check the overlay first, then fall back to the real filesystem. This minimizes IO.

4. **The MAX_SPECULATION_TURNS = 20 and MAX_SPECULATION_MESSAGES = 100** caps prevent runaway speculation from consuming too many resources.

5. **Pipelined suggestions create a chain**: Suggestion A generates Speculation A, which on completion generates Suggestion B, which can start Speculation B. Each link shares the growing prompt cache.
