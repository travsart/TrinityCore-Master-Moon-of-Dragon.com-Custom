# Team Memory Sync Service -- Arcanum Wiki

## What Is This?

Team Memory Sync synchronizes shared memory files between the local filesystem and a server-side API. Team memory is scoped per-repository (identified by git remote) and shared across all authenticated organization members. This enables teams to build a shared knowledge base that persists across sessions and team members.

## How It Works

### API Contract

The service communicates with the Anthropic API:
- `GET /api/claude_code/team_memory?repo={owner/repo}` -- fetch all entries
- `GET ...&view=hashes` -- fetch metadata + checksums only (bandwidth optimization)
- `PUT /api/claude_code/team_memory?repo={owner/repo}` -- upload entries (upsert semantics)
- 404 = no data exists yet for this repo

### Sync Semantics

- **Pull** overwrites local files with server content (server wins per-key)
- **Push** uploads only entries whose content hash differs from server checksums (delta upload)
- Server uses upsert: keys not in the PUT payload are preserved
- **File deletions do NOT propagate** -- deleting a local file will not remove it from the server; the next pull restores it locally

### State Management

All mutable state lives in a `SyncState` object (not module-level), giving tests natural isolation. State tracks:
- ETag for conditional requests
- Watcher suppression flags (to avoid sync loops when the watcher triggers on its own writes)
- Server checksums for delta computation

### File Watcher

`watcher.ts` monitors the team memory directory for changes and triggers push operations. It uses suppression to avoid infinite loops (local write from pull triggers watcher, which would trigger push).

### Secret Scanning

`secretScanner.ts` scans files before push to prevent accidental upload of API keys, credentials, or other secrets. `teamMemSecretGuard.ts` provides the guard logic. Files containing secrets are skipped with a `SkippedSecretFile` record.

### Size Limits

- `MAX_FILE_SIZE_BYTES = 250,000` per entry (server-enforced)
- `MAX_PUT_BODY_BYTES = 200,000` per PUT request (gateway body-size cap)
- Large pushes are split into sequential PUT batches
- Entry count limit is server-side and org-configurable (no client-side cap)

### Retry Logic

Uses exponential backoff with `MAX_RETRIES = 3` and `MAX_CONFLICT_RETRIES = 2` for 409 conflicts (concurrent modifications by other team members).

## Key Source Files

| File | Purpose |
|------|---------|
| `index.ts` | Core sync logic: fetch, push, delta computation |
| `watcher.ts` | Filesystem watcher with suppression |
| `secretScanner.ts` | Secret detection before push |
| `teamMemSecretGuard.ts` | Secret guard integration |
| `types.ts` | Schema definitions (Zod) and type exports |

## Configuration

- Feature flag: `TEAMMEM` (build-time feature gate)
- Requires first-party API provider with OAuth authentication
- Repo identification via `getGithubRepo()` git remote
- `TEAM_MEMORY_SYNC_TIMEOUT_MS = 30,000`
