# Prompt Suggestion Service -- Arcanum Wiki

## What Is This?

The Prompt Suggestion service predicts what the user will type next and displays it as a ghost suggestion in the input field. It also powers **Speculation** -- an Ant-only feature that speculatively executes the predicted prompt in the background, so when the user accepts the suggestion, the work is already done.

## How It Works

### Suggestion Generation

After each main thread response, `executePromptSuggestion()` fires as a post-sampling hook. It:

1. **Guards**: Skips if not main thread, fewer than 2 assistant turns, last response was an error, prompt cache is cold (>10K uncached tokens), suggestions disabled in settings, plan mode active, or rate limited.

2. **Generates**: Calls `generateSuggestion()` which runs a forked agent with a carefully crafted prompt asking the model to predict the user's next input in 2-12 words. The fork shares the parent's prompt cache by NOT overriding any API parameters (tools, model, thinking config, etc.).

3. **Filters**: `shouldFilterSuggestion()` rejects suggestions that are:
   - Single word (except allowed words like "yes", "push", "commit", slash commands)
   - Over 12 words or 100 characters
   - Multiple sentences
   - Evaluative ("looks good", "thanks")
   - Claude-voice ("Let me...", "I'll...")
   - Meta-text ("nothing to suggest", "silence")
   - Error messages
   - Have formatting (newlines, bold)
   - Have a label prefix ("Action: ...")

4. **Displays**: Sets the suggestion in app state for the TUI to render as ghost text.

### Speculation (Ant-only)

When a suggestion is generated and speculation is enabled, `startSpeculation()` runs the suggested prompt through a forked agent in the background:

**Isolation via overlay filesystem:**
- Write operations go to a temporary overlay directory (`~/.claude/tmp/speculation/<pid>/<id>/`)
- Reads check the overlay first (for files already written), then fall back to the real filesystem
- On acceptance, overlay files are copied to the real cwd

**Tool permissions during speculation:**
- Read/Glob/Grep: Always allowed
- Read-only Bash: Allowed (validated by `checkReadOnlyConstraints`)
- Write/Edit: Allowed only if permission mode is `acceptEdits` or `bypassPermissions`; otherwise stops speculation at that boundary
- Non-read-only Bash: Stops at boundary
- All other tools: Denied, stops at boundary

**Boundaries:** When speculation hits a tool it cannot safely execute, it records a `CompletionBoundary` (bash command, edit file path, denied tool) and aborts. The UI shows the speculation progress and boundary.

**Acceptance:** When the user types the exact suggested text (Tab to accept), `acceptSpeculation()`:
1. Copies overlay files to the real filesystem
2. Injects the speculated messages into the conversation
3. If speculation completed fully, no follow-up query needed
4. If incomplete (stopped at boundary), a follow-up query continues from where speculation left off

**Pipelined suggestions:** When speculation completes fully, it immediately generates the NEXT suggestion using the augmented conversation (original + speculated messages), creating a pipeline of predictions.

## Configuration

- Feature gate: `tengu_chomp_inflection` (GrowthBook)
- Env override: `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`
- Settings toggle: `promptSuggestionEnabled`
- Speculation: Ant-only, `speculationEnabled` in global config (default true)
- Disabled in non-interactive mode, swarm teammates, plan mode
