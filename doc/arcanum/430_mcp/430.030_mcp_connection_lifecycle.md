# MCP Connection Lifecycle
> Source: `12_mcp_client.md`

## Connection Flow

```
Config discovery (7 scopes) -> policy filtering
  -> partition: local (3 concurrent) / remote (20 concurrent)
  -> connectToServer() (memoized per config hash)
  -> Client.connect(transport) (30s timeout)
  -> fetchToolsForClient() (LRU cached, size 20)
  -> Tool[] registered into model context
```

## 5 Connection States

| State | Meaning |
|-------|---------|
| `connected` | Healthy with client, capabilities, cleanup fn |
| `failed` | Connection failed with error message |
| `needs-auth` | Server requires OAuth (15-min auth cache) |
| `pending` | Connection in progress (with reconnect tracking) |
| `disabled` | Explicitly disabled by user |

## Reconnection

Exponential backoff: 1s initial, 30s cap, max 5 attempts. After 3 consecutive terminal errors (ECONNRESET, ETIMEDOUT, EPIPE), manually triggers `client.close()`. Session expiry (HTTP 404 with code -32001) clears cache and retries once.

## Memoization

`connectToServer()` memoized by `name + JSON(config)`. Cache cleared on `client.onclose`, triggering fresh connection on next access. Tool/resource/command fetch caches also cleared.

## Needs-Auth Fast Path

File-backed auth cache (`mcp-needs-auth-cache.json`, 15-min TTL) skips doomed connections for servers that recently returned 401.
