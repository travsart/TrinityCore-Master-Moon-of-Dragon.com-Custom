# MCP Channel System -- Arcanum Wiki

## Overview

The channel system allows MCP servers to push inbound messages (from Discord, Slack, SMS, etc.) into the Claude Code conversation. Messages are wrapped in `<channel>` XML tags and enqueued. The system enforces a 6-layer gating mechanism to prevent unauthorized message injection.

## How It Works

### Message Format

```typescript
function wrapChannelMessage(serverName: string, content: string, meta?: Record<string, string>): string {
  // Produces: <channel source="serverName" chat_id="..." user="...">content</channel>
}
```

Meta keys are restricted to safe identifiers (`/^[a-zA-Z_][a-zA-Z0-9_]*$/`), and values are XML-escaped.

### 6-Layer Gating

`gateChannelServer()` enforces sequential gates:

| Gate | Check | Fail Reason |
|------|-------|-------------|
| 1. Capability | Server declares `claude/channel` in experimental capabilities | Not a channel server |
| 2. Runtime | `isChannelsEnabled()` via GrowthBook `tengu_harbor` | Feature unavailable |
| 3. Auth | `getClaudeAIOAuthTokens()?.accessToken` exists | Requires claude.ai auth |
| 4. Policy | `channelsEnabled: true` in managed settings | Org hasn't opted in |
| 5. Session | Server in `--channels` CLI flag list | Not in session's channel list |
| 6. Allowlist | Plugin in `allowedChannelPlugins` or GrowthBook ledger | Not approved |

### Permission Protocol

Channel servers can declare `claude/channel/permission` capability to participate in structured permission flows. The leader sends permission requests to the channel server, which relays to the user. The user responds with yes/no plus a 5-character request ID.

## Interesting Findings

**Channel permissions are pure yes/no.** Unlike the interactive permission handler which supports `updatedInput`, channel callbacks only relay binary approve/deny decisions. The user cannot modify tool input through a channel.

**The 6-gate architecture prevents accidental exposure.** Even if an MCP server declares channel capability, it must pass auth, policy, session, and allowlist checks before any messages reach the conversation.
