# WebSearchTool -- Arcanum Wiki

## Purpose

WebSearchTool performs web searches using Anthropic's server-side web search capability (`web_search_20250305`). It sends the query to a model with the web search tool enabled, streams results, and returns structured search hits with URLs. This tool is deferred (requires ToolSearch).

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `query` | string | Yes | Search query (minimum 2 characters) |
| `allowed_domains` | string[] | No | Only include results from these domains |
| `blocked_domains` | string[] | No | Never include results from these domains |

Cannot specify both `allowed_domains` and `blocked_domains` in the same request.

## Execution Flow

1. **Validation**: Non-empty query, no conflicting domain filters.
2. **Permission check**: Returns `passthrough` -- defers to general permission system with a suggestion to add an allow rule.
3. **Model query**: Creates a user message with the search query, builds a `BetaWebSearchTool20250305` schema (hardcoded to max 8 searches), and streams a model query.
4. **Progress streaming**: Tracks `server_tool_use` blocks for search queries, `web_search_tool_result` blocks for results. Emits `query_update` and `search_results_received` progress events.
5. **Result parsing**: `makeOutputFromSearchResponse()` processes the content blocks into a structured `results` array containing both string summaries and search hit objects (title + URL pairs).

## Key Implementation Details

### Haiku Optimization
A GrowthBook flag (`tengu_plum_vx3`) controls whether to use a Haiku-class model for web search. When enabled, the search uses `getSmallFastModel()` with `tool_choice: { type: 'tool', name: 'web_search' }` to force the tool call, and disables thinking. This is cheaper and faster.

### Search Limit
The web search tool is configured with `max_uses: 8` (src/tools/WebSearchTool/WebSearchTool.ts:83), hardcoded. This limits how many individual searches the model performs per WebSearchTool call.

### Provider Gating
WebSearchTool is only enabled for specific API providers (src/tools/WebSearchTool/WebSearchTool.ts:168-193):
- `firstParty`: Always enabled
- `vertex`: Only for Claude 4.0+ models (opus-4, sonnet-4, haiku-4)
- `foundry`: Always enabled (only ships models with web search support)
- All others: Disabled

### Source Citation Enforcement
The `mapToolResultToToolResultBlockParam` appends: "REMINDER: You MUST include the sources above in your response to the user using markdown hyperlinks." This is the mechanism that forces the model to cite sources.

### Progress Events
Two types of progress events are emitted during streaming:
- `query_update`: When a new search query is detected in the streaming JSON
- `search_results_received`: When a `web_search_tool_result` block completes, with result count

## Limits and Constraints

| Limit | Value |
|-------|-------|
| maxResultSizeChars | 100,000 |
| `shouldDefer` | true |
| Max searches per call | 8 |
| Min query length | 2 characters |
| Concurrency safe | Yes |
| Read only | Yes |

## Permission Requirements

Returns `passthrough` with a suggestion to add an allow rule for the tool. The permission mode is relatively permissive since web search doesn't modify local files.

## Error Handling

- **Empty query**: Validation error (errorCode 1)
- **Conflicting domains**: Both allowed and blocked specified (errorCode 2)
- **Web search errors**: `WebSearchToolResultError` content is caught and logged, with error message added to results
- **Null results**: Guard against null/undefined entries from JSON round-tripping (compaction, transcript deserialization)
