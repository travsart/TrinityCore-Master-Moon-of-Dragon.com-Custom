## Key Implementation Details

### Auto-Backgrounding
```typescript
// src/tools/AgentTool/AgentTool.tsx:72-77
function getAutoBackgroundMs(): number {
  if (isEnvTruthy(process.env.CLAUDE_AUTO_BACKGROUND_TASKS) ||
      getFeatureValue_CACHED_MAY_BE_STALE('tengu_auto_background_agents', false)) {
    return 120_000;
  }
  return 0;
}
```

### Worktree Cleanup
When worktree isolation is used, the tool cleans up after the agent completes. If the worktree has changes, they are preserved. The `hasWorktreeChanges()` and `removeAgentWorktree()` functions handle this lifecycle.

### Fork Subagent Mode
When `isForkSubagentEnabled()` is true, agents use a fork-based execution model where the parent's conversation context is shared via `buildForkedMessages()`. This is more token-efficient than starting from scratch.

### Teammate Spawning
The multi-agent path delegates to `spawnTeammate()` in `src/tools/shared/spawnMultiAgent.ts`. This creates a new Claude Code instance (in-process, tmux split-pane, or separate window) with its own identity, color, and mailbox for communication.

## Permission Requirements

Uses custom `checkPermissions` that checks:
- Agent deny rules via `getDenyRuleForAgent()`
- Filters agents by MCP server requirements
- Multi-agent team spawning has no additional permission gate

## Error Handling

- **Agent abort**: Caught as `AbortError`, partial results extracted via `extractPartialResult()`
- **Remote precondition failures**: Formatted via `formatPreconditionError()`
- **Worktree cleanup failures**: Logged but don't fail the overall operation
- **Missing MCP servers**: Agents with unmet MCP requirements are filtered from the available list

## Interesting Findings

1. The tool has two registered names: `Agent` (primary, from `AGENT_TOOL_NAME`) and `Task` (legacy alias from `LEGACY_AGENT_TOOL_NAME`). The alias ensures backward compatibility with older prompts/skills that reference "Task".

2. AgentTool's schema is the most dynamically gated in the codebase. Multiple fields are conditionally omitted based on feature flags, environment variables, and GrowthBook gates. The explicit `AgentToolInput` type widens the inference to always include all optional fields even when `.omit()` strips them.

3. The `invokingRequestId` is threaded through to the teammate context for "lineage tracing on tengu_api_* events" -- this enables tracking the causal chain from a parent's API call to a spawned teammate's actions.

4. In fork mode, the parent's full conversation messages are deliberately NOT passed to in-process teammates: "Passing the parent's full conversation here would pin it for the teammate's lifetime, surviving /clear and auto-compact."

5. The proactive/Kairos module is loaded via conditional `require()` instead of static import, enabling dead code elimination when the feature is not compiled in.
