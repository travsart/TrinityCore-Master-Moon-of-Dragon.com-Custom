# AgentTool -- Arcanum Wiki

## Purpose

AgentTool spawns subagent instances of Claude Code to handle delegated tasks. It supports synchronous (inline) and asynchronous (background) execution, worktree isolation, remote execution, multi-agent team spawning, and model selection per agent. This is one of the most complex tools in the codebase.

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `description` | string | Yes | Short 3-5 word task description |
| `prompt` | string | Yes | Full task instructions for the agent |
| `subagent_type` | string | No | Specialized agent type to use |
| `model` | enum | No | Model override: `sonnet`, `opus`, or `haiku` |
| `run_in_background` | boolean | No | Run as background task (hidden when fork mode or background tasks disabled) |
| `name` | string | No | Name for multi-agent addressing via SendMessage |
| `team_name` | string | No | Team context for spawning |
| `mode` | string | No | Permission mode (e.g., `plan` for plan approval) |
| `isolation` | enum | No | `worktree` (git worktree) or `remote` (CCR environment, internal only) |
| `cwd` | string | No | Override working directory (mutually exclusive with worktree isolation) |

## Execution Flow

### 1. Schema Gating
The input schema is dynamically constructed based on feature flags:
- `run_in_background` is omitted when background tasks are disabled OR fork subagents are enabled
- `cwd` is omitted unless the KAIROS feature is active
- Multi-agent fields (`name`, `team_name`, `mode`) are always present in the full schema

### 2. Agent Type Resolution
If `subagent_type` is provided, the tool looks up custom agent definitions from `.claude/agents/` directory. Built-in agent types include `GENERAL_PURPOSE_AGENT` and `ONE_SHOT_BUILTIN_AGENT_TYPES`. Agent definitions filtered by MCP requirements and permission deny rules.

### 3. Routing Decision
The tool decides how to execute based on multiple factors:
- **Multi-agent spawn**: If agent swarms are enabled and the model provides a `name`, spawns a teammate via `spawnTeammate()` from the shared module
- **Remote execution**: If `isolation: 'remote'`, launches in a CCR (Claude Code Remote) environment
- **Worktree isolation**: If `isolation: 'worktree'`, creates a temporary git worktree via `createAgentWorktree()`
- **Background async**: If `run_in_background: true`, registers as `LocalAgentTask` and returns immediately
- **Synchronous**: Default -- runs inline and blocks until completion

### 4. Agent Execution (Sync Path)
- Creates a unique agent ID via `createAgentId()`
- Builds the system prompt via `getSystemPrompt()` + `enhanceSystemPromptWithEnvDetails()`
- Assembles the tool pool for the subagent (which tools it can use)
- Runs the agent loop via `runAgent()` which manages the conversation turn loop
- Returns the agent's final result, filtered and summarized

### 5. Progress Reporting
Progress updates stream both AgentTool's own progress events AND shell progress events from sub-agent bash/powershell runs, so the SDK receives real-time tool_progress updates. The auto-background threshold is 120 seconds (when enabled via env var or GrowthBook gate).
