## Permission Requirements

Uses `checkWritePermissionForTool()`. Not concurrency-safe (default false), not read-only (default false).

## Error Handling

- **File not read**: Returns validation error (errorCode 2) with "Read it first" message
- **Staleness**: Returns error (errorCode 3) -- "File has been modified since read"
- **ENOENT** (new file): Proceeds normally, creates parent directories
- **Secrets in team memory**: Validation rejects with the secret guard's error message

## Interesting Findings

1. The Windows mtime fallback is notable: cloud sync services (OneDrive, Dropbox) and antivirus software can change file modification times without changing content. FileWriteTool handles this by comparing content when timestamps differ for full reads.

2. FileWriteTool logs a specific analytics event (`tengu_write_claudemd`) whenever CLAUDE.md is written, tracking how often the model modifies its own instructions.

3. The tool computes git diffs only for remote sessions (`CLAUDE_CODE_REMOTE`) behind a feature flag (`tengu_quartz_lantern`), suggesting this powers a diff view in the remote/web UI.
