# FileWriteTool -- Arcanum Wiki

## Purpose

FileWriteTool creates new files or completely overwrites existing files. It enforces a read-before-write requirement for existing files, tracks file history for undo support, notifies LSP servers and VS Code of changes, and preserves the model's intended line endings.

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `file_path` | string | Yes | Absolute path to the file to write |
| `content` | string | Yes | The content to write to the file |

## Execution Flow

### 1. Validation
- Rejects writes to team memory files containing secrets (`checkTeamMemSecrets`)
- Checks deny rules for the expanded path
- Skips filesystem operations for UNC paths (NTLM security)
- For existing files: requires `readFileState` entry (must Read before Write)
- For existing files: compares mtime against last read timestamp for staleness detection
- On Windows: performs content comparison as fallback when timestamps differ (cloud sync, antivirus can change mtimes without content changes)

### 2. Execution
- Discovers and activates conditional skills for the file path
- Notifies `diagnosticTracker.beforeFileEdited()`
- Creates parent directory if needed (`fs.mkdir`)
- If file history is enabled, creates a backup of the current file
- Re-reads the file synchronously for the critical section (staleness re-check)
- Writes content via `writeTextContent()` with LF line endings
- Notifies LSP server (`didChange` + `didSave`)
- Notifies VS Code via MCP (`notifyVscodeFileUpdated`)
- Updates `readFileState` with new content and mtime
- Logs analytics for CLAUDE.md writes
- Computes git diff for remote sessions

### 3. Result
Returns either `{ type: 'create' }` for new files or `{ type: 'update' }` with structured patch for existing files.

## Key Implementation Details

### Read-Before-Write Enforcement
The tool requires that the file has been read (or created) before it can be written. This prevents blind overwrites. The check at src/tools/FileWriteTool/FileWriteTool.ts:198-206:

```typescript
const readTimestamp = toolUseContext.readFileState.get(fullFilePath)
if (!readTimestamp || readTimestamp.isPartialView) {
  return {
    result: false,
    message: 'File has not been read yet. Read it first before writing to it.',
    errorCode: 2,
  }
}
```

### Line Ending Policy
FileWriteTool always writes LF line endings regardless of the original file's line endings (src/tools/FileWriteTool/FileWriteTool.ts:305). The comment explains: "Write is a full content replacement -- the model sent explicit line endings in `content` and meant them. Do not rewrite them." Previously the tool preserved original line endings, but this silently corrupted bash scripts with `\r` on Linux.

### Atomic Write Section
The code has a critical section between reading the current state and writing to disk. The comment at line 267 warns: "Please avoid async operations between here and writing to disk to preserve atomicity." The directory mkdir and file history backup are intentionally placed OUTSIDE this section.
