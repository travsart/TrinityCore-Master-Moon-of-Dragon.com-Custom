# Git Status & .gitignore Optimization

## Why This Matters

Claude Code injects `git status` output into the system prompt at session start. This output is **capped at ~2,000 characters**. If untracked files exceed the cap, useful information (branch, modified files) gets truncated.

## The 2K Cap Mechanism

At session start, Claude Code runs `git status --short` and injects the result into the context. The injection is capped at approximately 2,000 characters. If untracked file entries exceed this, the modified/staged entries that matter are buried or lost entirely.

## Before Optimization (VoxCore)

| Metric | Value |
|--------|-------|
| Untracked entries | 205 (19,045 chars) |
| Modified entries | 2 (56 chars) |
| Total output | 19,716 chars |
| Fits in 2K cap? | **No** -- always truncated |

96.6% of git status output was untracked noise from generated files.

## Noise Categories

1. **AI Studio audit reports** (147 entries, 74%) -- generated by `review_cycle.py`
2. **Published tool snapshots** (18 entries, 9%) -- each has its own GitHub repo
3. **Temp/build artifacts** (34 entries, 17%) -- `.tmp_*`, build logs, throwaway scripts

## Optimization Strategy

Add patterns for generated/temp/local-only files to `.gitignore`:
- `AI_Studio/Reports/` -- all generated reports
- `tools/publishable/` -- published repo snapshots
- `.tmp_*` -- temporary files
- `tools/mcp-voxcore-*/` -- MCP servers (own repos)
- `data/` -- generated output

## After Optimization

| Metric | Value |
|--------|-------|
| Untracked entries | 6 |
| Total output | ~636 chars |
| Fits in 2K cap? | **Yes** -- with room to spare |

22 gitignore patterns eliminated 199 of 205 untracked entries (97%).

## Key Takeaway

Every untracked file costs context tokens on every session. Maintaining `.gitignore` hygiene is a direct optimization for Claude Code performance.
