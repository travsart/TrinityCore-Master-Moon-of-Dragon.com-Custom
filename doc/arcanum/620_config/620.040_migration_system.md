# Config Migration System
> Source: `src/migrations/`, `settings_deep_dive.md`

## How Migrations Work

Claude Code uses idempotent config migrations that run at startup to upgrade settings files from older formats. Migrations transform `~/.claude/.config.json` (GlobalConfig) and `~/.claude/settings.json` (SettingsSchema) to match the current schema.

Each migration reads the current config, checks if a transformation is needed, and applies it. They run in sequence and are safe to re-run (idempotent).

## Key Migrations

- **Model remapping**: Old model IDs (e.g., `claude-3-opus`) remapped to current naming
- **Permission format upgrade**: Legacy rules normalized to current `ToolName(pattern)` syntax
- **Tool name normalization**: `Task` -> `Agent`, `KillShell` -> `TaskStop`
- **enableAllProjectMcpServers**: Migrating from project config to `settings.json`
- **Cowork settings split**: `--cowork` reads from `cowork_settings.json`

## Settings File Hierarchy (Merge Order)

| Priority | Source | Path |
|----------|--------|------|
| 0 (lowest) | Plugin settings | (internal) |
| 1 | User settings | `~/.claude/settings.json` |
| 2 | Project settings | `.claude/settings.json` |
| 3 | Local settings | `.claude/settings.local.json` |
| 4 | Flag settings | `--settings` CLI flag |
| 5 (highest) | Policy settings | OS-specific managed path |

Policy cascade: remote API > HKLM/plist (MDM) > `managed-settings.json` + drop-ins > HKCU.

## Config Home Override

`CLAUDE_CONFIG_DIR` env var overrides `~/.claude` for all config paths.
