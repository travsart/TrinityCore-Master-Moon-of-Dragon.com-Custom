## Hold-to-Talk Detection

Terminals lack `keyUp` events. The system detects key release via auto-repeat timing gaps. When a key is held, the terminal emits repeated keypresses at 30-80ms intervals. A **200ms gap** signals release.

**Bare-char activation** (e.g., Space): Requires 5 rapid presses within 120ms gaps to activate. First 2 presses flow through to input (so single space types normally). On activation, flow-through chars are stripped.

**Modifier combos** (e.g., `meta+k`): Activate on first press -- unambiguous intent.

CJK full-width space (U+3000) is also accepted when the hold key is space.

## Project Keyterms (50-term boost)

`voiceKeyterms.ts` builds a vocabulary hint list sent to Deepgram for accuracy:

**Global terms**: `MCP`, `symlink`, `grep`, `regex`, `localhost`, `codebase`, `TypeScript`, `JSON`, `OAuth`, `webhook`, `gRPC`, `dotfiles`, `subagent`, `worktree`

**Dynamic terms**: Project root basename, git branch words (split on camelCase/kebab/snake), recent file name words. Total capped at 50 terms.

## Silent-Drop Replay Bug

~1% of sessions hit a "session-sticky CE pod" bug where the server accepts audio but returns zero transcripts. When `finalize()` resolves via `no_data_timeout` with `hadAudioSignal=true`, the system replays the full buffered audio on a fresh WebSocket once.

Audio buffer is bounded: 32KB/s x ~60s max = 2MB.

## Finalize Flow

When recording stops, `CloseStream` is sent (deferred via `setTimeout(0)` to flush queued audio). Resolution triggers in order:

1. `TranscriptEndpoint` after `CloseStream` (~300ms -- fast path)
2. No-data timeout (1.5s -- server has nothing)
3. WebSocket close event (~3-5s -- server teardown)
4. Safety timeout (5s -- last resort)

## Audio Level Visualization

RMS amplitude is computed from PCM buffers with sqrt curve for visual range. A 16-bar histogram is published to the voice context store. The cursor renders as a Unicode block waveform during recording with 50ms animation frames.
