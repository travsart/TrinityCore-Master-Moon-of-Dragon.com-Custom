# Bash Execution Internals
> Source: `06_tool_pipeline.md`, `10_permissions.md`

## Shell Execution

Bash commands spawn via the system shell. On Windows, Git Bash is used. `CLAUDE_CODE_SHELL_PREFIX` env var wraps bash commands. Hook commands support `shell: 'powershell'` for PowerShell on Windows.

## Working Directory

`CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR` resets cwd to project root after each command. Without it, cwd persists between calls but shell state (variables, functions) does not -- each command gets a fresh shell.

## Timeouts

| Setting | Default | Max |
|---------|---------|-----|
| `BASH_DEFAULT_TIMEOUT_MS` | 60,000 (60s) | -- |
| `BASH_MAX_TIMEOUT_MS` | 300,000 (5min) | -- |
| `BASH_MAX_OUTPUT_LENGTH` | ~30,000 chars | -- |

The model can request custom timeouts up to `BASH_MAX_TIMEOUT_MS`.

## Background Commands

`run_in_background: true` spawns the command detached. Output is collected via `TaskOutput` tool later. Disabled by `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`.

## Concurrency Safety

Bash `isConcurrencySafe()` is input-dependent. Read-only commands (ls, cat, git status) are safe for parallel execution. Write commands run serially.

## Dangerous Pattern Detection

Auto mode strips allow rules for dangerous patterns: `python`, `node`, `ssh`, `eval`, `exec`, `sudo`, `npm run`, plus 20+ others. These require classifier approval in auto mode.
