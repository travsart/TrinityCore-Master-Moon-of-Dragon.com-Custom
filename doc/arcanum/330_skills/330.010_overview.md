# Skill System Architecture -- Arcanum Wiki

## Overview

The skill system is Claude Code's extensibility layer for reusable, prompt-based capabilities. Skills are markdown files (`SKILL.md`) with YAML frontmatter that define specialized instructions, allowed tools, argument schemas, and execution modes. The system supports 8 distinct discovery sources, dynamic discovery during file operations, conditional path-based activation, and two execution modes (inline context modification and forked sub-agent).

## How It Works

### The 8 Discovery Sources

Skills are loaded in parallel from all sources by `getSkillDirCommands()`, then combined with first-wins deduplication:

```
1. Managed     (~/.anthropic/.claude/skills/)      -- Enterprise policy
2. User        (~/.claude/skills/)                 -- Personal
3. Project     (.claude/skills/ per parent dir)    -- Project-scoped
4. Additional  (--add-dir .claude/skills/)         -- Explicit CLI dirs
5. Legacy      (~/.claude/commands/, .claude/commands/) -- Deprecated
6. Bundled     (compiled into binary)              -- Ship with CLI
7. Plugin      (marketplace + built-in plugins)    -- Addon ecosystem
8. MCP         (MCP server prompts w/ skill_md)    -- Remote servers
```

Dynamic skills (discovered during file operations) are merged at query time, inserted before built-in commands.

### Skill Directory Format

Skills must use the directory format: `<skill-name>/SKILL.md`. Single `.md` files at the top level of `/skills/` are NOT supported (only the legacy `/commands/` path supports them).

### Execution Modes

**Inline** (default): The skill's content is processed via `processPromptSlashCommand()` and injected as user messages into the current conversation. Allowed tools, model, and effort overrides are applied via a `contextModifier`.

**Forked** (`context: fork` in frontmatter): The skill runs as an isolated sub-agent via `runAgent()`. The agent gets its own message history, system prompt, and tool set. Results are collected and returned to the parent conversation.

### Deduplication

Skills are deduplicated using `realpath()` to resolve symlinks. The same physical file loaded through different directory paths produces only one skill entry. First-wins semantics apply.

### Skill Listing in System Prompt

Skills are surfaced to the model via system-reminder attachments. The listing gets 1% of the context window (in characters). Per-entry descriptions are capped at 250 characters. When the full listing exceeds the budget, non-bundled descriptions are truncated; in extreme cases, reduced to names-only.

## Interesting Findings

**The Skill tool prompt uses "BLOCKING REQUIREMENT" language.** The model is told: "When a skill matches the user's request, this is a BLOCKING REQUIREMENT: invoke the relevant Skill tool BEFORE generating any other response." This ensures skills are invoked as tools rather than described in text.

**MCP skills cannot execute shell commands.** Inline shell command execution (`!command` syntax) is explicitly blocked for MCP-loaded skills, treating them as untrusted remote content.
