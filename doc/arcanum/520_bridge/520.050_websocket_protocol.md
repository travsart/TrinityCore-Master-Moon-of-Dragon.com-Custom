# WebSocket Protocol
> Source: `17_bridge.md`

## Message Format (SDKMessage)

Messages flow as discriminated unions:

**Outbound (CLI -> CCR)**:
- `{type: 'user', message, uuid, session_id}` -- user prompt
- `{type: 'assistant', message, uuid, session_id}` -- assistant response
- `{type: 'result', subtype: 'success', duration_ms, num_turns}` -- turn result
- `{type: 'control_request', request_id, request}` -- permission request
- `{type: 'control_response', response}` -- response to server control

**Inbound (CCR -> CLI)**:
- `{type: 'user', message, uuid}` -- remote user's prompt
- `{type: 'control_response', response: {behavior: 'allow'|'deny'}}` -- permission
- `{type: 'control_request', request}` -- server commands (initialize, set_model, interrupt)

## Server Control Requests

| Subtype | Action |
|---------|--------|
| `initialize` | Returns commands, models, account, pid |
| `set_model` | Changes active model |
| `set_max_thinking_tokens` | Adjusts thinking budget |
| `set_permission_mode` | Switches permission mode |
| `interrupt` | Aborts current operation |

## Echo Deduplication

`BoundedUUIDSet` (ring buffer, 2000 entries) prevents self-echo, re-delivery on SSE reconnect, and flush-gate interleaving.

## Transport Details

**v1**: WebSocket for reads (auto-reconnect, ping/pong), HTTP POST for writes via `SerialBatchEventUploader` (100ms buffer, max batch 100).

**v2**: SSE for reads (sequence-number resume via `Last-Event-ID`), HTTP POST for writes. Heartbeat via `PUT /worker` at 20s intervals. Epoch-based identity (409 = superseded).
