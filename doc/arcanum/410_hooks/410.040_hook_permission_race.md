# Hook Permission Race
> Source: `09_hooks_system.md`, `10_permissions.md`

## The 4-Way Race

Permission dialogs race four async sources simultaneously:

1. **User interaction** (local terminal) -- approve/reject/abort callbacks, 200ms grace
2. **Bridge permission** (CCR/claude.ai) -- remote user approval with `updatedInput` support
3. **Channel permission** (Telegram, iMessage) -- yes/no only via MCP channel servers
4. **Hooks + Classifier** (background) -- PermissionRequest hooks + bash classifier

First source to call `claim()` via `createResolveOnce()` wins. All others become no-ops.

## Hook Allow Does NOT Bypass Rules

Critical invariant in `resolveHookPermissionDecision()`:

```
Hook says 'allow':
  -> checkRuleBasedPermissions() still applies
  -> Deny rule overrides hook allow
  -> Ask rule forces dialog despite hook approval
  -> Only if no rules match -> hook allow takes effect

Hook says 'deny':
  -> Immediate deny (no override possible)
```

## Behavior Precedence

When multiple hooks run in parallel: **deny > ask > allow > passthrough**. A single deny overrides any number of allow hooks.

## Denial Tracking

| Limit | Value | Action |
|-------|-------|--------|
| Consecutive denials | 3 | Fall back to user prompt |
| Total denials | 20 | Fall back to user prompt |
| Headless + limits exceeded | -- | `throw AbortError` |
